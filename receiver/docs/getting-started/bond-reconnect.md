# R10：保存绑定与自动回连

基于用户已确认可用的 R9。CH582F 使用 `receiver/firmware/CH582-dev/stick-CH582F-bond-reconnect-r10.bin` 或对应 `.hex`。本轮无需读取串口日志，通过断电、开关手柄和游戏输入即可验收。

2026-10-07 用户反馈：R10 自动回连测试正常。具体断电组合及密钥重新加密未分别提供结果；该反馈确认了实际回连功能，尚不能单独验证 SDK 的密钥存储。

## 使用

1. 烧录并重启开发板。首次让 Stadia 手柄进入橙灯闪烁的配对模式，短按开发板扫描键并释放。
2. 连接后等待数秒，检查按键／摇杆能够输入。程序只在 HID 通知订阅成功后记住该手柄。
3. 以后开发板上电后会自动寻找已保存的手柄，无需按扫描键；关掉再打开手柄，或掉线后恢复距离，也会自动回连。失败时等待间隔依次为 1、2、4、8、10 秒，之后上限保持 10 秒，另有每轮扫描时间。
4. 更换手柄或清除旧配对：开发板正常运行时长按扫描键满 3 秒，随后把目标手柄置于配对模式。程序结束扫描／连接后清除手柄记录及 SDK 绑定，再开始新手柄扫描；无需再次短按。清除期间不会保存旧连接的迟到回调。

短按在松开时生效：空闲时扫描、已连接时断开并重新连接保存的手柄；扫描中短按暂停扫描及自动重试，再短按恢复。长按只触发一次清除，松开不会额外触发短按。长按功能用于固件运行时，启动时 BOOT + USB 仍按原 ISP 烧录方式操作。

## 保存方式

配对密钥由 WCH Bond Manager 保存：`BLE_SNV=1`、`GAPBOND_CENT_BONDING_ENABLED=TRUE`、`GAPBOND_BOND_AUTO=TRUE`。首次连接主动请求配对，失败策略为 `GAPBOND_FAIL_NO_ACTION`，保留对无需安全协商即可读取 HID 的情况的兼容性。原生 SDK 负责密钥协商与后续加密，应用不复制或打印密钥。

另一个记录只包含可用手柄的地址及地址类型，用于上电选择目标；它不等于加密绑定。地址记录位于 DataFlash 相对地址 `0x6E00`、`0x6F00` 两个 256 字节擦除页，每次交替提交，带 CRC、版本、递增代数与最终提交标记，并检查 ISP 返回值和写后读回。同一身份重复连接不重写。部分写入不覆盖上一条已提交记录，清除使用较新的墓碑记录，避免旧页在重启后恢复旧身份。

| 区域 | CH582 SDK | CH592 SDK |
|---|---|---|
| 应用手柄记录 | DataFlash `0x6E00–0x6FFF` | DataFlash `0x6E00–0x6FFF` |
| SDK SNV 默认起始／配置大小 | `0x7E00`／256 字节 | `0x7000`／256 字节 |

SDK 的 Flash 容量为 32 KB DataFlash（相对 `0x0000–0x7FFF`），不是应用 CodeFlash 地址。本实现不写 CodeFlash，编译时校验应用页对齐、容量和 SDK SNV 不重叠。移植时如果自制板已有其它持久化数据，先重新分配区域，使用 `BOARD_PEER_STORE_ADDR` 覆盖并保持两个相邻擦除页。

原厂 HAL 的 SNV 读写回调未向协议栈传递底层 ISP 错误，本地保留 SDK 原样；因此 SDK 的保存完成状态不能代替实物断电后的密钥恢复验证。应用地址记录有独立的 ISP 错误处理和读回校验，但不能由此声称配对密钥已物理保存。刷写工具执行全片／DataFlash 擦除会丢失保存信息，应重新配对。

当前地址匹配支持公开地址和稳定的 random static 地址。本次手柄为公开地址；未实现通过 IRK 解析任意变化的隐私地址，也未增加多手柄切换。

## 验收与限制

按顺序验证首次配对及输入、仅开关手柄、仅重启开发板、两者一起断电重启、运行时长按清除再配对。重启测试中只正常开机手柄，不要主动重新进入配对模式，否则不能区分保存回连与重新配对。烧录后第一次连接是建立 R10 的保存记录，旧 R9 未保存绑定，因此不能直接期待已有断电记录。

主机模拟覆盖双页提交中断、CRC 错误、清除、代数及计时回绕、目标地址过滤、回连退避、连接超时取消、配对等待和清除期间的迟到事件；CH582 标准／诊断及 CH592 诊断交叉编译通过。主机模拟不执行闭源 WCH 协议栈的实际配对、加密或 SNV，R10 的真实断电保存及无线回连仍需上板验收。R9 的内部 32K、固定 25 ms 间隔、发现顺序及 USB／震动优化均保留。
